## Эпизод 1. Сборка проекта: неполные скрипты CMake

**Запрос:** «Don't modify source files or explain them. Generate README.md, AGENTS.md, docs/, and write tests using ctest».

**Что выдала сборка:**

```text
CMake Error at CMakeLists.txt:16 (add_subdirectory):
  The source directory /home/alex/vuz/sem3-oop/tests
  does not contain a CMakeLists.txt file.
```

Далее, после восстановления `tests/CMakeLists.txt`:

```text
/usr/bin/ld: cannot find -ldataset: No such file or directory
```

**Разбор агентом.** Обе ошибки — не про C++, а про подключение каталогов:

- в корневой `CMakeLists.txt` не было `add_subdirectory(src)`, поэтому цель
  `ds_load` вообще не создавалась;
- в `src/CMakeLists.txt` отсутствовал `add_subdirectory(dataset)`, из-за чего
  в `target_link_libraries(ds_load PRIVATE dataset)` слово `dataset`
  интерпретировалось не как имя цели CMake, а как системная библиотека
  (`-ldataset`), которую линковщик пытается найти в системе;
- каталог `tests/` остался без `CMakeLists.txt`, поэтому падало
  `enable_testing(); add_subdirectory(tests)`.

**Что сделано агентом.** Восстановлены/добавлены только строки подключения
каталогов в трёх файлах CMake (`add_subdirectory(src)`,
`add_subdirectory(dataset)`, `tests/CMakeLists.txt`). Исходный код на C++
не изменялся.

**Что студент должен уметь объяснить:** разницу между целью CMake и обычным
именем библиотеки и почему `add_subdirectory` должен идти до
`target_link_libraries`.

## Эпизод 4. Тесты: ошибка препроцессора

**Сообщение компилятора:**

```text
error: macro "CHECK_NEAR" passed 4 arguments, but takes just 3
   60 |         CHECK_NEAR(onehot.matrix[{i, 0}], expected_val, 1e-12);
```

**Разбор агентом.** Макросы видят только запятые на уровне верхних скобок.
`{i, 0}` записано в фигурных скобках, которые препроцессор не считает
группирующим символом, поэтому аргумент разбивается на четыре. Ошибка
исправляется не изменением макроса, а взятием проблемного аргумента в
дополнительные круглые скобки: `CHECK_NEAR((m[{i, 0}]), expected_val, ...)`.

## Эпизод 5. Тесты: срабатывание AddressSanitizer в собственном тесте

**Сообщение санитайзера:**

```text
ERROR: AddressSanitizer: heap-use-after-free ... in median(...)
    #6 main /home/alex/vuz/sem3-oop/tests/test_quantiles.cpp:24
freed by thread T0 here: ... std::vector<double>::~vector()
previously allocated ... vector(std::initializer_list<double>, ...)
```

**Разбор агентом.** Тест создавал `std::span` над временным объектом:

```cpp
const std::span<const double> odd_sorted{std::vector<double>{1., 2., 3., 4., 5.}};
```

`std::span` — невладеющее представление: вектор-временный уничтожается в конце
инициализирующего выражения, а ссылка остаётся. Санитайзер корректно поймал
use-after-free; исправление — завести именованный вектор и строить `span`
от него. Это отличная иллюстрация того, почему по условию вычислительные
функции обязаны принимать `std::span<const double>`: владение остаётся
по-прежнему у вызывающего, и следить за временем жизни придётся именно ему.
