## Эпизод 1. Рефакторинг CART и поддержка весов bootstrap ($s$ vs $W$)

### Запрос пользователя
- Анализ требований ТЗ лабораторной работы 4 к расширению дерева CART из Лабораторной 3.
- Разделение понятий: число различных исходных индексов ($s$) и суммарная кратность ($W = \sum count_i$).
- Обеспечение обратной совместимости метода `fit` с новым `fit_with_counts`.

### Принятые решения
1. **Расширение `SplitFinder`**:
   - Параметр `std::span<const size_t> counts = {}` добавлен в конец методов `find_best` и `find_for_feature`. Пустой `span` интерпретируется как единичные веса ($1$).
   - Формулы обновления агрегатов переведены на взвешенные суммы: $S_L += w \cdot y$, $W_L += w$. Для критерия Джини: $A_L += 2 a w + w^2$, $A_R += -2 b w + w^2$.
   - Обновление $O(1)$ на каждый шаг сохранено.
2. **Семантика ограничений размеров**:
   - `min_samples_split` и `min_samples_leaf` проверяются строго по числу уникальных объектов $s$, а не сумме кратностей $W$.
3. **Безопасность состояния модели**:
   - В `CartRegressor::fit_with_counts` и `CartClassifier::fit_with_counts` в начале выставляется `m_fitted = false`, чтобы при выбросе исключения модель не оставалась в обученном состоянии.
   - Добавлена проверка на наличие хотя бы одного положительного веса: при `object_ids.empty()` выбрасывается `EmptyData`.

## Эпизод 2. Архитектура параллелизации на `std::jthread` (C++20)

### Запрос пользователя
- Реализация многопоточного обучения ансамбля деревьев и параллельного вычисления предсказаний.
- Требование ТЗ: использование строго `std::jthread` из C++20, исключение гонок данных, обработка исключений из рабочих потоков через `std::exception_ptr` и `std::rethrow_exception()`.

### Принятые решения
1. **Класс `ParallelWorker` (`src/models/common/parallel.hpp`)**:
   - Выделена переиспользуемая RAII-абстракция над группой `std::jthread`.
   - При `n_jobs <= 1` вычисления идут последовательно на вызывающем потоке без создания `std::jthread`.
   - Вектор `std::vector<std::exception_ptr> errors(m_num_workers, nullptr)` выделяется заранее до запуска потоков.
   - Внутри рабочего потока блок `try / catch (...)` перехватывает исключение через `std::current_exception()`, сохраняет его в ячейку потока и запрашивает останов остальных потоков через `global_stop.request_stop()`.
   - По выходу из блока деструкторы `std::jthread` гарантированно дожидаются завершения всех потоков (join), после чего сохранённая ошибка пробрасывается вызывающему коду через `std::rethrow_exception()`.
2. **Применение в `ForestTrainer` и `ForestRegressor` / `ForestClassifier`**:
   - Устранено дублирование кода создания потоков в обучении и предсказании.
   - Ограничение числа потоков $\min(n\_jobs, B)$ исключает создание избыточных потоков.

## Эпизод 4. Диагностика компилятора, санитайзеров и ThreadSanitizer

### Обнаруженные проблемы и решения
1. **Перемещение заголовков в `engine/`**:
   - При вынесении ядра деревьев в подкаталог `engine/` сломались инклуды в `src/models/decision_trees/stump.cpp`.
   - *Исправление*: инклуды обновлены на `engine/criteria/gini.hpp`, `engine/split_finder.hpp`.
2. **Падение CLI при отсутствии `--max-depth`**:
   - В `src/cli.cpp` обнаружено дублирующее присваивание `result["max-depth"].as<size_t>()`, вызывавшее `option_has_no_value` при запуске без опции `--max-depth`.
   - *Исправление*: удалена лишняя строка, параметр читается только при наличии флага.
3. **ThreadSanitizer в WSL2 (Linux 6.6)**:
   - При сборке с `-fsanitize=thread` тесты аварийно завершались до `main()`: `FATAL: ThreadSanitizer: unexpected memory mapping` из-за высокой энтропии рандомизации адресов ядра (`vm.mmap_rnd_bits = 32`).
   - *Исправление*: в `CMakeLists.txt` добавлена опция `SANITIZE_THREAD` с флагом `-no-pie`. Все тесты под TSan прошли чисто без единого предупреждения о гонках данных.
