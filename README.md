## Правило определения типа признака

Порог — `numeric_column_threshold` в `config.hpp`, значение **8**:

1. Если хотя бы одно непропущенное значение столбца не разбирается как число
   (`std::from_chars` не дошёл до конца токена), признак **категориальный**.
2. Если все значения разбираются как числа, но различных значений строго меньше
   `numeric_column_threshold`, признак **категориальный**.
3. В остальных случаях признак **числовой**.

## Предобработка

Предобработка выполняется только после подтверждения пользователя и состоит из
трёх шагов.

### 1. Заполнение пропусков

Значения берутся из уже вычисленной статистики (`DatasetInfo`); повторный
расчёт по данным с подставленными значениями не выполняется.

- **числовые признаки** — по выбранной стратегии (`--fill`): `median`
  (медиана), `mean` (среднее), `zero` (ноль);
- **категориальные признаки** — дополнительной категорией `__MISSING__`
  (`category_imputation` в `config.hpp`).

Категория для пропусков добавляется поверх исходного словаря: исходные
категории сохраняются и не переименовываются.

### 2. Масштабирование числовых признаков

По умолчанию — **min-max** приведение к диапазону `[0, 1]`; доступны также
стандартизация и robust-масштабирование (`--scale`):

| Режим      | Преобразование                                   |
| ---------- | ------------------------------------------------ |
| `minmax`   | $x' = \dfrac{x - x_{\min}}{x_{\max} - x_{\min}}$ |
| `standart` | $x' = \dfrac{x - \mu}{\sigma}$                   |
| `robust`   | $x' = \dfrac{x - Q_{0.5}}{Q_{0.75} - Q_{0.25}}$  |

Все величины ($x_{\min}$, $x_{\max}$, $\mu$, $\sigma$, квантили) берутся из
ранее посчитанной статистики признака и заново по данным не вычисляются.

Вырожденный случай (знаменатель равен нулю — признак константный): значение
заменяется на `1`, то есть столбец остаётся константным равным единице.
Единица выбрана потому, что это верхняя граница min-max, и она не создаёт
ложного разброса там, где исходный признак его не имеет.

### 3. Кодирование категориальных признаков

По умолчанию — **one-hot** (`--encode onehot`); альтернатива — **ordinal**.

- **one-hot** — один столбец на категорию, значения 0 или 1. Имя столбца
  составное: `признак_категория`, например `department_sweing`.
- **ordinal** — один столбец с целочисленным кодом категории, имя столбца
  совпадает с исходным именем признака.

Порядок категорий **детерминирован**: словарь собирается в `std::set`, то есть
категории упорядочены лексикографически. Одинаковый вход всегда даёт одни и те
же коды и одинаковый порядок столбцов матрицы.

Соответствие «номер столбца — имя признака» хранится в
`TransformedDataset::feature_names`: для one-hot это составные имена, для
ordinal — исходные имена.

**Где ordinal вносит ложный порядок.** Ordinal-кодирование навязывает меткам
численный порядок (`finishing`=0, `sweing`=1), которого в данных нет. Это
существенно для моделей, чувствительных к величине признака и к расстояниям:
линейная и логистическая регрессия, kNN, SVM, методы с регуляризацией по весу
признака — они начнут считать, что «sweing» на единицу «больше», чем
«finishing». Для моделей, основанных на разбиениях по значению (деревья
решений, случайный лес, градиентный бустинг на деревьях), порядок несущественен:
они сравнивают код с порогом, и любое разбиение на две группы доступно и при
one-hot. В нашем датасете категориальные признаки (`quarter`, `department`,
`day`, `no_of_style_change`) — метки без естественного порядка, поэтому
по умолчанию выбран one-hot.

## Бинарный формат

Матрица сохраняется в файл без текстового преобразования: значения пишутся
напрямую как `double` в представлении IEEE 754. Формат файла:

| Смещение | Поле       | Тип                 | Размер (x86-64)   | Назначение                            |
| -------- | ---------- | ------------------- | ----------------- | ------------------------------------- |
| 0        | `m_rows`   | `std::size_t`       | 8                 | число строк                           |
| 8        | `m_cols`   | `std::size_t`       | 8                 | число столбцов                        |
| 16       | `m_layout` | `enum class Layout` | 4                 | `0` — `RowMajor`, `1` — `ColumnMajor` |
| 20       | значения   | `double[]`          | `8 · rows · cols` | массив значений матрицы               |

Итоговый размер файла — `20 + 8 · rows · cols` байт.

Порядок хранения элементов определяется полем `m_layout`: при `RowMajor`
элемент `(i, j)` лежит по смещению `i · cols + j`, при `ColumnMajor` —
`j · rows + i`. Схема одинакова для обоих способов — меняется только порядок
обхода.

Запись и чтение симметричны: `Matrix::save` последовательно пишет размеры,
раскладку и затем массив значений; `Matrix::load` сначала читает размеры,
под них выделяет память (`m_data.resize(rows * cols)`) и только после этого
читает данные — по условию работы именно такой порядок обязателен.

Соответствие «номер столбца — имя признака» в файл **не записывается**: оно
хранится в памяти в `TransformedDataset::feature_names` и передаётся
следующим программам напрямую, а не через файл.

**Почему формат годится только для учебной задачи:**

- нет метки формата и номера версии: изменение структуры ломает чтение старых
  файлов без единого предупреждения;
- размеры полей не зафиксированы — `sizeof(std::size_t)` и размер
  `enum class` зависят от платформы и компилятора, файл с 32-битной системы
  нечитаем на 64-битной и наоборот;
- порядок байтов не нормализуется: файл, записанный на big-endian машине,
  на little-endian прочитается как набор бессмысленных чисел;
- нет контрольной целостности (контрольной суммы, длины, магии): обрезанный
  или испорченный файл не обнаруживается, а чтение мусора из него
  проверяется только санитайзером;
- нет проверки на переполнение при вычислении `rows · cols`.

# Лабораторная работа 2\*. Решающий пень

Реализован решающий пень (decision stump) — дерево глубины 1: выбираются
один признак и один порог, значения `<=` порога идут в левый лист, остальные —
в правый. Листья выдают константу: среднее (регрессия) или наиболее частую
категорию (классификация). Обучение, предсказание и критерии качества
представлены в ядре через интерфейсы `IModel`, `IDecisionStump`,
`ISearchCriteria`; ошибки — иерархией исключений ядра.

## Алгоритм и сложность

Наивный перебор порогов для каждого признака стоит `O(d·n²)`: для каждого
из `d` признаков каждый из `n` объектов сравнивается с остальными.
Реализация сортирует индексы по значению признака (`O(n log n)`) и проходит
по отсортированному порядку один раз с инкрементальным критерием
(`O(1)` на шаг), что даёт `O(d·n log n)` на обучение.

Критерии (максимизируются):

- регрессия — `G = S_L²/m_L + S_R²/m_R`, суммы и счётчики обновляются за O(1);
- классификация — `H = A_L/m_L + A_R/m_R`, `A = Σ f_i²`, обновления
  `A_L += 2a+1`, `A_R += 1-2b`.

Порог — среднее двух соседних различающихся значений (`std::midpoint`).
Ограничение `min_samples_leaf` запрещает маленькие листья; если допустимого
разбиения нет, модель вырождается в константную (`split_feature()` и
`split_threshold()` возвращают `std::nullopt`). При равных оценках побеждает
первая найденная пара (меньший индекс признака, затем меньший порог) —
обход детерминирован.

## Замеры времени

Бенчмарк в `test_stump_naive.cpp` (`benchmark_fast_vs_naive`, закомментирован
в `main`, чтобы не замедлять `ctest`): случайные данные, три прогона на
одной машине.

| Реализация                      | Сложность      | n = 2000, d = 20 |
| ------------------------------- | -------------- | ---------------- |
| ядро (`DecisionStumpRegressor`) | `O(d·n log n)` | ~310 мс          |
| наивный эталон                  | `O(d·n²)`      | ~31 с            |

Ускорение — примерно **100×**. Наивная реализация из теста — только эталон
для сверки: ядро и наивный пень на всех случайных выборках выдают одинаковые
предсказания (`test_regression_matches_naive`).
