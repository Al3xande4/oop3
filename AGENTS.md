# AGENTS.md

Инструкции для агента и разработчика, работающего с этим репозиторием.

## О проекте

Учебный проект кафедры ООП (семестр 3): консольная программа загрузки,
анализа и предобработки табличного датасета. Язык — C++20, сборка — CMake.
Лабораторные работы 2–5 и графическое приложение из работы 6 опираются на
данные, подготовленные этой программой.

Датасет: `data/garments_worker_productivity.csv` (UCI, см. README).

## Структура репозитория

```
CMakeLists.txt          корневой скрипт: стандарт C++, санитайзеры, подкаталоги
src/                    консольное приложение (ввод-вывод с пользователем)
  main.cpp              разбор аргументов командной строки, вывод сводки и статистики
  dataset/CMakeLists.txt
  dataset/config.hpp    вся специфика датасета: разделитель, признак пропуска,
                        порог типа, число интервалов гистограммы, категория пропуска
  dataset/column.hpp    столбцы: NumericColumn / CategoricalColumn, std::variant
  dataset/dataset.{hpp,cpp}   загрузка CSV, определение типа, impute, transform
  dataset/feature_info.hpp    статистика: mean, variance, quantile, median, сводки
  dataset/imputation.hpp      стратегии заполнения числовых пропусков
  dataset/scaling.hpp         стратегии масштабирования
  dataset/category_encoding.hpp  enum class CategoryEncoding
  dataset/transformed.{hpp,cpp}  Matrix, TransformedDataset, бинарная сериализация
  dataset/helpers.hpp   trim
tests/                  тесты, регистрируемые в CTest
data/                   датасет (в .gitignore, не коммитится)
docs/                   журнал работы агента и примеры вывода
```

Библиотека ядра — `dataset` (каталог `src/dataset`), приложение — `ds_load`.
Вся логика загрузки, анализа и преобразований обязана лежать в `dataset`,
`main.cpp` — только разбор опций, запросы к пользователю и форматирование
вывода.

## Сборка и запуск

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/src/ds_load --help
./build/src/ds_load --dataset data/garments_worker_productivity.csv
```

Для сборки без санитайзеров (если инструменты недоступны):

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DSANITIZE=OFF
```

Release-сборка: `-DCMAKE_BUILD_TYPE=Release` (санитайзеры включаются только
в Debug).

## Правила

- Стандарт C++20, расширения компилятора выключены (`CMAKE_CXX_EXTENSIONS OFF`).
- Сборка должна идти без предупреждений при `-Wall -Wextra`.
- В Debug включены AddressSanitizer и UndefinedBehaviorSanitizer; тесты
  обязаны проходить без срабатываний.
- Пропуски — только `std::optional` (в столбце) / `std::nullopt`; недопустимо
  кодировать пропуск особым числом (`-9999`) или пустой строкой.
- Разнотипные столбцы и статистика признаков — через `std::variant`.
- Выбор стратегии заполнения, масштабирования и кодирования — через
  `enum class` или абстрактный базовый класс со стратегией; строки из
  командной строки разбираются в одном месте и не размазываются по коду.
- Вычислительные функции (среднее, дисперсия, квантили) принимают данные
  через `std::span<const double>` или другое невладеющее представление.
- Все константы, специфичные для датасета (разделитель, обозначение пропуска,
  наличие заголовка, порог типа), живут только в `src/dataset/config.hpp`.
  Новые подобные литералы в других файлах недопустимы.
- Число признаков, их имена и типы берутся из файла, а не из констант кода.
- Ошибки ввода-вывода и разбора — через сообщение пользователю и ненулевой
  код возврата, не через `assert` и не через аварийное завершение.
- Тесты — отдельные программы без фреймворка, возвращают ненулевой код
  при несовпадении, регистрируются через `add_test`.

## Что агенту можно и нельзя (по условиям лабораторной работы)

Можно (с записью в `docs/agent_log/lab_1.md`):

- разбор сообщений компилятора и санитайзеров;
- разбор возможностей стандартной библиотеки, синтаксиса C++, CMake;
- автоматическое получение метаданных таблицы (имена столбцов, типы, вид
  записи категорий);
- генерация README и форматирование вывода в консоль.

Нельзя (это содержание работы, выполняется студентом):

- определение типа признака;
- расчёт статистик и квантилей;
- заполнение пропусков, масштабирование, кодирование категорий;
- бинарная сериализация;
- проектирование представления датасета.

Код, сгенерированный агентом, студент должен уметь объяснить и переписать
самостоятельно. Важные промпты и эпизоды фиксируются в
`docs/agent_log/lab_1.md`.

## Перед коммитом

1. `cmake --build build -j` — без ошибок и предупреждений.
2. `ctest --test-dir build --output-on-failure` — все тесты зелёные.
3. Если менялся вывод программы — обновить пример в README.
4. Если менялся формат файла или правила разбора — обновить README и, при
   необходимости, журнал агента.
